# Code review — M22 (Foundation: creator profile + editable prompts)

Scope: `git diff 5cf4aba^..2a0db87` (commits `5cf4aba` + `2a0db87`). Effort: high.

## Summary
M22 is solid. The only real issues are a single root cause repeated at three read
sites: **owner-scoping is left to RLS, but the `editor` SELECT policy on these
tables is `has_role(editor)` with no owner filter**, so any user who *also* holds
the `editor` role sees every owner's rows. The app explicitly supports multi-role
users (e.g. admin + advisor), so admin + editor is reachable. Today the primary
user is admin-only, so these are **latent** — but they are genuine data-isolation
bugs and trivially fixable.

Confirmed against live policies:
- `creator_profile` → `Editor reads creator_profile` = `has_role(auth.uid(),'editor')`
- `prompt_overrides` → `Editor reads prompt_overrides` = `has_role(auth.uid(),'editor')`

## Findings

### 1. `supabase/functions/generate-script/index.ts:630` — wrong owner's prompt can be used (HIGH)
`loadPromptOverrides` queries `prompt_overrides` by `.in("slug", slugs)` with **no
`owner_id` filter**. For a caller who also has the `editor` role, RLS returns all
owners' overrides and `new Map(rows.map(r => [r.slug, r.content]))` keeps the last
row per slug → generation can run with **another owner's system prompt / manifesto
/ hook bank**.
- Tell: `loadCreatorProfile` ~17 lines below *does* filter `.eq("owner_id", ownerId)`;
  the loader's comment even claims "RLS already scopes both reads to the calling
  owner" — false here.
- Fix: add `.eq("owner_id", user.id)` to the `prompt_overrides` select.

### 2. `src/lib/api/creatorProfile.ts:39` — Settings page can throw for multi-role users (MEDIUM)
`fetchCreatorProfile()` does `.select("*").maybeSingle()` with no `owner_id`
filter. For an admin who also has the `editor` role, the editor policy returns
multiple `creator_profile` rows → `.maybeSingle()` throws ("multiple rows
returned"), breaking the Marca/Cuestionario tab load.
- Fix: `.eq("owner_id", user.id).maybeSingle()`.

### 3. `src/lib/api/promptOverrides.ts:70` — Prompts IA tab shows a foreign override (MEDIUM)
`fetchPromptOverrides()` `.select("*")` with no owner filter; for admin + editor
it returns all owners' rows, so `overrideBySlug` in `PromptsTab` collides across
owners and can render another owner's text + the "Personalizado" badge (and the
reset/save then act on the wrong scope's expectation).
- Fix: filter by the current owner.

## Recommended remediation
Add explicit `.eq("owner_id", <current user>)` to all three reads (and audit the
other M23–M26 reads that follow the same "RLS will scope it" assumption —
`prompt_overrides` is also read in `generate-youtube-structure`, and
`creator_profile` is read in `generate-script` + `generate-youtube-structure`,
both of which *do* scope by owner). After fixing #1, redeploy `generate-script`.
